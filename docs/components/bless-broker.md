# Bless broker

The expansion-request flow. When an agent needs more capability than its current envelope allows (egress, config-dir writes, system config), it asks the bless broker. The broker gates the request behind an un-forgeable nonce, rate-limits, and requires biometric approval for high-risk expansions.

## Why this exists

Landlock is irreversible mid-session — you cannot loosen an envelope once applied. So mid-session expansion requires restarting the session in a new, wider domain. The bless broker is the human-in-the-loop gate for that restart.

Without it: either the agent is stuck (can't complete a legit task that needs egress) or the agent self-expands (the bypass path). The broker makes expansion possible but human-controlled.

## Mechanism

1. **Agent requests expansion** via a daemon socket call: `castellan-bless request --want egress --reason "need to fetch from npm registry"`.
2. **Daemon generates a nonce** and sends it to the notification UI via dbus (NOT to the agent's environment — the agent cannot forge this).
3. **Notification UI** shows the request: agent, project, current tier, requested expansion, reason, quale risk card (advisory — which paths this expansion typically touches, hub-risk).
4. **Human approves or rejects** via the notification (click Approve / Reject) or via `castellan-bless approve <nonce>` in a terminal.
5. **If approved:** daemon kills the current session, mints a new wider envelope, restarts the session in the new domain. The session UUID is preserved (event spine continues); the envelope change is logged.
6. **If high-risk (egress or config-dir writes):** fp-toggle biometric required for approval. `castellan-bless approve <nonce>` calls `fp-toggle-internal verify`.
7. **If rejected:** session continues in its current envelope. Agent is told "expansion denied" (so it can adapt).

## Rate limiting (commitment #10)

- Max **3 expansions per session**. After the 3rd, further requests are auto-denied with "expansion limit reached."
- **Cooling-off period:** 5 minutes between expansions. Prevents rapid-fire social engineering.
- **Per-project daily cap:** 10 expansions per project per day. Resets at midnight.

## Nonce (commitment #10)

The nonce is generated by the daemon and sent to the notification UI via dbus. The agent never sees it. `castellan-bless approve <nonce>` requires the nonce; the agent cannot construct a valid approve call without it. This closes A10 (forged approval).

## Risk card (quale)

Each request includes a quale risk card (advisory): hub-risk of the paths this expansion would touch, co-change signal, blast-radius estimate. This is the owned `quale` primitive used as advisory input — NOT load-bearing, NOT a claim. It informs the human; it doesn't decide for them.

## Antagonism survivors

- A10 (forged approval): closed — nonce via dbus, agent cannot forge.
- B5 (forged bless nonce): closed — same.
- C-variant (social engineering at scale): rate-limited (3/session, 10/project/day, 5min cooling-off). Residual: a patient attacker can still social-engineer within the limits. Documented.

## Residual risks

- Human social-engineering: the broker informs (risk card, biometric, cooling-off) but cannot prevent a user who genuinely approves a bad expansion. Documented.
- The restart UX: expanding kills and restarts the session. The agent's in-memory state is lost; it resumes from the event spine + its harness's session file. Some harnesses handle this gracefully (Claude Code's session JSONL), others may not. Documented per-harness.

## Dependencies

- `castellan-core` (SessionId, EnvelopeProfile)
- `castellan-daemon` (nonce generation, dbus, restart orchestration)
- `castellan-envelope` (new ruleset minting)
- `castellan-freezer` (kill + restart sequence)
- `zbus` (dbus)
- Owned primitives: `fp-toggle` (BUILT, biometric), `quale` (BUILT, advisory risk card).

## Status

Approval ledger + rate limits + daemon-side one-shot grants are shipped and verified live (`cdb419d`): a grant is consumed at spawn, keyed `project:want`, in-memory only (the agent cannot forge a grant without the daemon), and overrides the trust tier floor for that expansion. The dbus notification flow and the mid-session envelope re-mint (kill → relaunch same session id in a wider domain) remain designed, not built. Landlock cannot be loosened mid-session, so the current semantics are "grant the next launch," not "widen this session."
