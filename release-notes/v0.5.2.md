Castellan is a Linux trust boundary for AI coding agents. It starts an agent inside a kernel-enforced envelope (Landlock, seccomp, cgroups) so writes stay in the project, every write is witnessed, and a panic button freezes every session. It is a narrow jail: write containment, undo and canaries, not read or egress blocking.

## Install

Requires Linux 7.0+ with Landlock ABI 4+, systemd with a user session, and cgroup v2. Verified on kernels 7.0.3, 7.1.8, 7.2.5 and 7.2.11 (x86_64). The x86_64 binaries are built on Ubuntu 24.04 and need glibc 2.39 or newer.

```sh
tar xzf castellan-v0.5.2-linux-x86_64.tar.gz
./castellan-v0.5.2-linux-x86_64 preflight     # all 6 checks must pass
```

Both binaries are in the tarball and `service install` finds the versioned daemon beside the CLI, so no rename or symlink is needed. `aarch64` is built and inspected by the same workflow and has not been executed here; treat it as build-verified only.

## Changes

**0.5.2** — `service install` now reports success only once the daemon answers on its socket, instead of when systemd has merely spawned the process.
**0.5.1** — `service install` could not find the daemon in a release tarball; the documented extract-and-run journey ended with no service.

Both were found by running the published tarball's own instructions inside an Omarchy 4.0.4 VM.

## Requirements and limitations

Confinement applies to agents launched through castellan. A harness started any other way runs unconfined. Reads are not restricted, and same-uid processes outside the session can read state and the evidence ledger; the ledger itself is write-protected. The threat model and its residual list are in `docs/THREAT_MODEL.md`.
